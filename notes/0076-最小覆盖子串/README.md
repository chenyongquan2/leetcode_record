# 76. 最小覆盖子串

- 难度：困难　|　CodeTop 频率：135
- 链接：https://leetcode.cn/problems/minimum-window-substring/

## 思路

- **滑动窗口（左闭右开 `s[lo, hi)`）**：`need = Counter(t)` 记录每个字符还需要多少个，`window` 记录窗口内相关字符的出现次数，`valid` 统计"已经凑够数量"的字符**种数**。
- 右指针 `hi` 不断吸收字符：只关心 `need` 里的字符，`window[c] += 1` 后若恰好 `window[c] == need[c]`，说明字符 `c` 凑够了，`valid += 1`。
- 当 `valid == len(need)`（所有字符都凑够）时窗口合法，进入内层循环收缩 `lo`：即将移出的字符 `d` 若正处于 `window[d] == need[d]` 的临界状态，说明再移就不合法了——此刻窗口是当前右边界下最紧的合法窗口，先尝试更新答案，再 `valid -= 1` 退出收缩。
- 与常见模板"每轮收缩前更新答案"略有不同：本写法把更新答案放在合法性即将被打破的临界点，跳过左端无关字符后才记录，同样正确且记录的窗口更紧。

## 复杂度

- 时间：O(|s| + |t|)（lo、hi 各最多走 |s| 步）
- 空间：O(字符集大小)（need / window 两张计数表）

## 知识点：滑动窗口用 valid 计数"凑够的字符种数"来判断窗口合法

覆盖型滑动窗口（窗口需包含 t 的全部字符含重复）用两张计数表 `need`、`window`，再用 `valid` 记录已凑够数量的**字符种数**，窗口合法即 `valid == len(need)`。关键细节：增减 `window[c]` 时只在**恰好相等**（`window[c] == need[c]`）的临界点更新 `valid`——右扩时 `+1` 后相等说明刚凑够，左缩时相等说明再移出就缺了（先更新答案再 `valid -= 1`）。用 `==` 而不是 `>=`，因为计数一次只变 1，临界点只会经过一次。
