# record-note：录入一道刷题笔记

用户发来一道已完成的题目，将其录入 `notes/` 并刷新 README/PROBLEMS 表格。全程由 Claude 执行，用户不需要手动跑脚本。

## 输入解析

从用户消息中提取：

- **题号**（必须）：如 `3`、`146`、`剑指Offer22`、`补充题4`。用户只给了题目名或只给了代码时，先从 `data/codetop.json` 按标题反查；无法唯一确定时向用户确认，不要猜。
- **代码**：Python、C++，或两者。判断依据代码语法，不要求用户声明语言。
- **思路**（可选）：用户对解法的说明。
- **掌握程度**（可选）：0-3，用户没说时默认 1；用户表达"很熟/秒了"→3，"还行"→2，"勉强/看了题解"→1。

## 执行步骤

1. **脚手架**：`python scripts/new_note.py <题号>`。
   - 该脚本对已存在的文件不覆盖，因此重复录入同一题是安全的（进入"复习模式"，见下）。
   - 若提示题号找不到：先 `python scripts/fetch_codetop.py` 更新数据再试一次；仍找不到则告知用户并按相同目录结构手动创建（frontmatter 的 `fid` 用用户给的题号）。
2. **写入题解**：把用户代码分别写入该题目录下的 `solution.py` / `solution.cpp`（文件头保留"题号、标题、链接、一句话思路"注释）。用户只提供了一种语言时，**删除另一个未使用的模板文件**，使表格只显示实际存在的题解。
3. **填写笔记 `README.md`**：
   - frontmatter：`done: true`，`mastery` 按解析结果。
   - 思路：优先整理用户的原话；用户没写思路时根据代码总结出简洁思路，并在末尾注明"（由代码自动总结，可自行修改）"。
   - 复杂度：填写实际的时间/空间复杂度。
   - 知识点（可选）：用户提到易错点/常搞错的知识点（或对话中刚讲解过）时，在"复杂度"和"易错点 / 回顾记录"之间为每条知识点写一个 `## 知识点：<短标题>` 小节。`gen_readme.py` 会把所有笔记里的这类小节自动汇总到根目录 `TIPS.md` 供集中复习，因此标题要写成脱离本题也能看懂的一句话。
   - 易错点 / 回顾记录：追加一行 `- <今天日期>：<简短记录>`。
4. **验证 Python 题解**：若有 `solution.py`，在 `if __name__ == "__main__"` 下补 2-3 个基于题目示例的断言并运行；失败时报告用户，不要静默修改用户的解法逻辑。C++ 只做静读检查，不强制编译。
5. **刷新表格**：`python scripts/gen_readme.py`（会同时重新生成 `TIPS.md` 知识点汇总页）。
6. **提交**：`git add` 本次涉及的文件（该题目录 + README.md + PROBLEMS.md，若知识点有变动还有 TIPS.md），commit message 用 `note: <题号>. <题名>`；只 commit 不 push。
7. **汇报**：告诉用户该题在表格中的频率排名、当前总进度（x/1155），以及笔记文件路径。

## 复习模式（该题已有笔记时）

不重建脚手架，改为：更新/追加题解代码，在"易错点 / 回顾记录"追加一行当天记录，按用户表述调整 frontmatter 的 `mastery`，然后同样执行刷新表格、提交、汇报。

## 一次多题

用户一次发多道题时逐题执行上述流程，最后一次性 commit（message 列出所有题号），汇报用汇总表。

## 注意

- 所有文件读写用 UTF-8；目录名由 `scripts/common.py` 的 `note_dirname()` 决定，不要自造格式。
- 不修改 `data/codetop.json` 中的频率数据；频率只来自爬取。
- 用户代码原样保留（含其注释与风格），只允许补充文件头注释与测试断言。
